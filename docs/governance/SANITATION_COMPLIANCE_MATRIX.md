# Matriz de Conformidade de Saneamento

> **Versão do documento:** 1.9

> **Atualizado em:** 2026-04-12
> **Objetivo:** Matriz viva de conformidade para rastrear execuções de saneamento técnico

---

## 1. Objetivo

Esta matriz é a fonte única de verdade para rastrear todas as execuções de saneamento técnico aplicadas ao projeto Gemini-Mini-IDE. Cada execução que modifica governança, documentação, CI ou higiene do repositório deve ser registrada aqui com rastreabilidade completa.

## 2. Escopo do Saneamento Técnico

O saneamento técnico cobre:

- documentação de governança (políticas, processos, registros de decisão);
- alinhamento de pipeline CI/CD;
- enforcement de política de branches;
- higiene de código (remoção de código morto, limpeza de dependências, limpeza do repositório);
- coerência documental.

O saneamento técnico **não** cobre:

- desenvolvimento de features;
- correções de bugs em código de aplicação;
- mudanças arquiteturais;
- otimização de performance.

## 3. Política de Branches

| Regra | Descrição |
|---|---|
| **Branch oficial** | `main` é a única branch oficial |
| **Branches provisórias** | Branches temporárias para desenvolvimento; devem ser mergeadas ou descartadas prontamente |
| **Destino de merge** | Todo trabalho deve ter caminho claro para `main` |
| **Sem branches órfãs** | Branches sem destino de merge são consideradas abandonadas |

## 4. Gate Mínimo de Merge

Todo merge em `main` deve passar:

| Gate | Comando |
|---|---|
| Lint | `pnpm lint` |
| Type check | `pnpm typecheck` |
| Testes | `pnpm test` |
| Pipeline | `bash scripts/active/pipeline.sh` |

Nenhuma execução é considerada completa se não passar em todos os gates.

## 6. Como Usar Esta Matriz

1. **Antes de iniciar** uma execução de saneamento, adicione uma nova linha com campos de status marcados como pendente se a execução for apenas planejada.
2. **Durante a execução**, atualize as colunas Ação e Arquivos conforme o trabalho progride.
3. **Após validação**, preencha Validações Executadas e Resultado.
4. **Após commit/merge**, preencha Commit Final com o hash materializado oficial.
5. **Nunca** marque Resultado como passou se qualquer gate de validação falhou.
